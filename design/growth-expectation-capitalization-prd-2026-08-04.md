# 成长股预期资本化诊断 PRD

> 日期：2026-08-04
>
> 状态：产品方案已确认，待拆分 OpenSpec change
>
> 暂定能力名：Growth Expectation Capitalization Diagnostic
>
> 中文名：成长预期资本化诊断
>
> 所属能力：G2「深：可信 Investment Thesis」

## 1. 文档目的

本文定义一个面向成长股估值的重要诊断能力：

> 判断当前股价已经提前资本化了多少公司未来尚未创造的价值，以及当前价格隐含的增长率、增长持续时间和预期透支程度。

本能力不试图给出一个看似精确的“目标价”，而是把成长股当前价格背后的市场假设显式化，帮助用户回答：

- 当前市值中，有多少能够由现有经营能力支撑？
- 有多少价值必须依靠未来增长才能兑现？
- 当前价格相当于提前交易了未来多少年的增长？
- 市场隐含的增长要求是否超出了公司经营证据能够支持的范围？
- 如果未来经营结果不及预期，估值风险主要来自哪里？

本文是产品需求与能力边界文档，不替代：

- `design/three-goal-capability-roadmap.md`；
- `design/architecture-decisions.md`；
- `design/total-design.md`；
- 后续 OpenSpec proposal、design、spec 和 tasks；
- 具体模型实现、参数校准与真实样本验证报告。

## 2. 背景与问题定义

### 2.1 用户场景

面对一只成长股，仅判断“PE 很高”“股价涨了很多”或“市场情绪过热”是不够的。

真正需要判断的是：

> 当前股价中，有多少来自公司已经具备的经营能力，有多少来自未来增长预期；这些未来预期需要公司以多高的速度、持续多少年才能兑现。

例如，两只股票当前 PE 都是 50 倍：

- 公司 A 拥有较高 ROIC、较长增长跑道和稳定现金流，50 倍估值可能主要反映可验证的长期增长；
- 公司 B 的利润增长依赖短期景气、资本投入或情绪推动，同样的 50 倍估值可能已经提前消耗了大量不确定的未来价值。

因此，本能力不能停留在横向或历史估值比较，而应建立从“当前价格”反推“市场隐含经营要求”的桥梁。

### 2.2 第一性原理表达

本能力采用以下价值拆分：

```text
当前市值
= 现有经营能力价值
+ 市场已定价的未来增长价值
```

进一步与公司经营证据支持的增长范围比较：

```text
市场已定价的未来增长价值
= 可信未来增长价值
+ 超出可信增长范围的预期溢价
```

因此，系统最终需要区分：

1. 现有业务已经创造并可持续的价值；
2. 未来增长能够合理支撑的价值；
3. 依赖过高增长、过长增长期或情绪延续才能成立的价值。

## 3. 产品目标

### 3.1 核心目标

针对进入 G2 深研的成长型候选股，同时输出两类结果：

1. **未来价值占比**
   - 当前市值中有多少比例依赖未来增长；
   - 现有经营能力价值能够覆盖当前市值的多少。

2. **已前置兑现年限**
   - 在给定增长情景下，当前价格相当于提前交易了未来多少年的增长；
   - 在给定增长年限下，当前价格隐含公司需要实现多高的增长率。

### 3.2 辅助目标

- 显式展示关键假设及其敏感性；
- 区分公司事实、市场预期和用户确认的估值假设；
- 将结果纳入 `InvestmentThesis` 的估值、假设、风险和 `what_would_change_my_mind`；
- 为 G3 提供可持续监控的“原始隐含预期基线”；
- 在数据不足时诚实降级，不强行生成数值结论。

### 3.3 成功标准

用户看到结果后，应能够用自然语言复述：

> 当前价格大约有多少由现有经营支撑；剩余部分要求公司以什么速度增长多久；这个要求与我认可的可信增长区间相比，是合理、偏激进还是明显透支。

## 4. 非目标

本能力不承担：

- 自动给出买入、持有、减仓或卖出指令；
- 输出单一且确定的目标价；
- 用高估值直接淘汰成长股；
- 用近期涨跌、换手率或舆情热度替代价值分析；
- 在 G1 全市场路径运行完整 reverse DCF；
- 在缺少关键字段时静默填充行业默认值；
- 把研报共识当作公司事实；
- 连接券商、自动下单或管理真实账户；
- 在未经真实验证的情况下将 LongPort/Longbridge 候选字段视为已可用数据。

## 5. 用户故事

### 5.1 初次研究

作为用户，我希望在研究一只成长股时看到当前价格隐含的增长要求，从而判断这是一家“好公司但价格已经透支”，还是“高估值但增长仍可能支撑”。

### 5.2 情景比较

作为用户，我希望比较保守、基准和乐观三种增长情景，而不是被单一 DCF 数值误导。

### 5.3 假设确认

作为用户，我希望系统自动准备历史数据和建议参数区间，但由我确认折现率、维护性资本开支比例、可信增长率和成熟期估值锚。

### 5.4 持续跟踪

作为持仓用户，我希望后续财报公布时，系统能够比较实际增长与买入时市场隐含增长，判断公司是在追上预期、维持预期还是落后于预期。

## 6. 在 G1/G2/G3 中的能力落位

### 6.1 G1「快」

G1 不运行完整估值模型，只允许输出低成本风险标签：

```text
high_expectation_risk
```

标签可以参考：

- 当前 PE/PB 与历史分位；
- 当前市值与三年利润、现金流的关系；
- 近期价格和换手率是否显著升温；
- 基础数据是否足以进入 G2。

约束：

- 高预期风险不等于排除；
- 不因成长股高 PE 自动降低到不可研究；
- 不在 G1 输出“透支未来 N 年”的精确数值；
- 不把 V0 诊断结果纳入全市场硬 Gate 或主排序。

### 6.2 G2「深」

G2 是本能力的主要运行位置。

成长预期资本化诊断应成为 `InvestmentThesis` 的结构化组成部分，回答：

- 当前价格由什么支撑；
- 市场正在为什么样的未来付费；
- 关键增长假设是什么；
- 哪些事实支持或反驳这些假设；
- 在什么经营结果下需要改变判断。

### 6.3 G3「拿得住」

G3 不重新发明估值模型，而是读取 G2 形成的原始基线：

- 初始隐含增长率；
- 初始隐含高增长年限；
- 初始未来价值占比；
- 用户确认的可信增长区间；
- 关键经营变量和失效条件。

后续监控实际收入、利润、现金流、ROIC 或其他关键经营指标是否追上原始预期。

G2 Gate 通过前，本能力不得被用于驱动 G3 自动状态机。

## 7. 核心概念与输出定义

### 7.1 现有经营能力价值

`current_business_value`

假设公司不再依赖超额增长，仅维持经过正常化后的当前经营能力时，对应的股权价值区间。

V0 使用：

- EPV proxy 作为主锚；
- 成熟期估值倍数作为交叉验证。

V1 再升级为基于 NOPAT、投入资本、维护性再投资和净债务的完整 EPV。

### 7.2 市场已定价的未来增长价值

`priced_growth_value`

```text
priced_growth_value
= current_market_value - current_business_value
```

该值保留正负号：

- 正值：市场正在为未来增长付费；
- 负值：市场价格低于现有经营能力价值，表现为市场折价；
- 不允许将负值静默截断为 0。

### 7.3 未来价值占比

`priced_growth_share`

```text
priced_growth_share
= priced_growth_value / current_market_value
```

必须以区间形式输出，反映现有业务价值锚的不确定性。

### 7.4 隐含增长率

`implied_growth_rate`

在用户确认增长持续年限、折现率和终值假设后，反求当前市值要求公司实现的增长率。

### 7.5 隐含高增长持续年限

`implied_high_growth_duration`

在用户确认增长率、折现率和终值假设后，反求当前市值要求高增长持续的年数。

### 7.6 已前置兑现年限

`value_pulled_forward_years`

在选定的可信增长情景下，市场已经提前资本化的未来增量经营价值所对应的等价年限。

该指标是估值情景指标，不表示：

- 股价一定会在对应年数内不涨；
- 公司增长会在该年份突然结束；
- 投资者必须持有对应年数才能回本。

### 7.7 预期透支

`expectation_overdraft`

比较市场隐含增长要求与公司经营证据能够支持的可信增长区间：

```text
expectation_gap
= market_implied_assumption - credible_assumption_range
```

初始输出等级：

- `within_credible_range`
- `above_base_case`
- `above_credible_upper_bound`
- `not_evaluable`

具体阈值必须经过历史样本和案例校准，不在 PRD 中硬编码。

## 8. 估值模型方案

### 8.1 已确认方案

采用双锚情景模型：

```text
主锚：EPV proxy
交叉验证：成熟期行业/可比公司估值
```

不采用单一 PE 判断，也不在当前阶段直接建设完整 reverse DCF。

### 8.2 V0 EPV proxy

V0 优先采用股权侧 owner earnings proxy：

```text
normalized_owner_earnings
= normalized_operating_cashflow - estimated_maintenance_capex

equity_epv_proxy
= normalized_owner_earnings
   / (cost_of_equity - maintenance_growth)
```

其中：

- `normalized_operating_cashflow`：基于当前可获得历史期进行正常化；
- `estimated_maintenance_capex`：总资本开支乘以用户确认的维护性资本开支比例；
- `cost_of_equity`：用户确认或由系统建议区间；
- `maintenance_growth`：只允许采用低增长假设。

同时提供净利润资本化交叉检查：

```text
mature_multiple_value
= normalized_net_profit * confirmed_mature_pe
```

限制：

- `CONSTRUCT_LONG_ASSET` 是总资本开支代理，不能直接等同维护性资本开支；
- 只有三年数据时，正常化能力有限；
- V0 结果必须标记为 diagnostic；
- 两个锚差异过大时，不允许机械取平均，必须展示分歧及原因。

### 8.3 Reverse 模式

系统提供两种互斥求解方式：

#### 模式 A：固定增长率，求增长年限

输入用户认可的保守、基准、乐观增长率，反求当前价格要求该增长持续多少年。

#### 模式 B：固定增长年限，求增长率

输入 3 年、5 年、8 年等增长窗口，反求当前价格要求达到的年化增长率。

系统不得在没有额外约束的情况下同时宣称唯一求出了增长率和增长年限。

### 8.4 V1 完整模型

V1 在数据和验证条件满足后升级为：

- NOPAT 正常化；
- 维护性与成长性再投资拆分；
- ROIC 和增量 ROIC；
- 再投资率；
- 净债务；
- 股权稀释；
- 多阶段增长路径；
- reverse DCF 或 economic profit；
- 多年度分析师一致预期及其修订轨迹。

## 9. 数据需求与当前充足性

### 9.1 当前可用字段

| 数据 | 当前状态 | V0 用途 |
|---|---|---|
| 当前价格、市值、PE、PB | 可用 | 当前市场价值与估值背景 |
| 近三年营收、净利润 | 可用 | 粗略正常化盈利和增长趋势 |
| 近三年经营现金流 | 可用 | owner earnings proxy |
| `CONSTRUCT_LONG_ASSET` | 可用但口径有限 | 总资本开支代理 |
| 总资产、流动/非流动负债、股本 | 可用 | 财务质量辅助分析 |
| 五年 PE/PB 历史序列与分位 | 可用 | 历史估值背景和异常提示 |
| 研报 EPS、PE、评级分布 | 能力存在但当前覆盖不足 | 市场预期辅助证据 |
| 价格和换手率序列 | 可用或部分降级 | 情绪与交易热度背景 |

### 9.2 当前缺失或不可靠字段

| 数据 | 影响 |
|---|---|
| 5–10 年历史财务 | 无法充分跨周期正常化 |
| EBIT、税费、NOPAT | 无法形成标准企业侧 EPV |
| 折旧摊销 | 无法准确调整经营现金流和资本开支 |
| 营运资本变化 | 无法解释现金流波动 |
| 货币资金和有息债务 | 无法可靠完成企业价值到股权价值转换 |
| 维护性/成长性资本开支拆分 | 容易系统性低估成长股现有业务价值 |
| ROIC、增量 ROIC | 无法判断增长是否真正创造价值 |
| 再投资率 | 无法验证增长率的经济可实现性 |
| 多年度 consensus 路径 | 无法建立完整市场预期曲线 |
| consensus revisions 和 surprise | 无法判断市场预期正在上修还是下修 |
| 成熟期同行识别 | 行业平均可能本身处于高估状态 |
| 研发资本化调整 | 容易低估研发型成长公司的现有经营能力 |

### 9.3 2026-08-04 当前缓存核验

本次只读核验得到：

- `basic.json`：72 只，均有价格、市值、PE、PB；
- `financials.json`：71 只，均有三年净利润、经营现金流和总资本开支代理；
- `valuation.json`：71 只，其中 70 只有至少 250 个 PE/PB 历史点；
- `research.json`：当前缓存仅 1 只；
- `basic.industry`：当前 72 只样本均为空。

这些数据说明 V0 在小样本上具备计算基础，但不代表：

- 全 A 股数据覆盖已经验证；
- 研报共识能够批量稳定获得；
- 行业和成熟期同行锚已经可用；
- 数据已经达到自动化决策级质量。

### 9.4 LongPort/Longbridge 使用边界

LongPort/Longbridge 文档或 SDK 中存在财报、估值历史、行业估值和一致预期候选能力，但在 A 股 runtime probe 完成前：

- 不计入当前可用字段；
- 不进入正式计算主链；
- 不作为 `quality_status=passed` 的依据；
- 不允许替换为未经验证的 fallback；
- 只能在 shadow probe 中记录字段、单位、报告期、覆盖和失败状态。

## 10. 产品交互

### 10.1 已确认交互模式

采用：

```text
自动取数
+ 系统建议假设区间
+ 用户确认关键假设
+ 情景计算
```

系统负责准备事实数据和可追溯的建议区间，用户保留最终估值判断。

### 10.2 用户需要确认的关键假设

最低确认项：

- 正常化盈利口径；
- 维护性资本开支占总资本开支的比例区间；
- 折现率或成本权益区间；
- 可信增长率的保守、基准和乐观情景；
- 成熟期 PE 或成熟期可比公司范围；
- reverse 求解模式：固定增长率或固定增长年限。

系统可以给出建议值，但必须：

- 标记建议值来源；
- 允许用户调整；
- 保存用户确认值；
- 禁止把默认值伪装为公司事实；
- 对明显非法输入给出校验和错误提示。

### 10.3 输入校验

至少覆盖：

- 折现率必须大于永续增长率；
- 维护性资本开支比例必须处于允许范围；
- 增长年限必须为正数且不超过模型上限；
- 增长率、利润和现金流口径必须一致；
- 市值、利润和现金流必须使用同一币种和缩放单位；
- 负利润、负现金流和周期顶部样本不能套用普通正增长模型；
- 金融行业不得直接使用普通工业企业 EPV 模型；
- 数据过期、缺失或来源失败时必须停止或降级。

### 11.3 可解释性要求

每个结果必须能够追溯：

- 使用了哪些报告期；
- 采用了哪个价格和市值时点；
- 哪些字段来自公司事实；
- 哪些字段来自市场预期；
- 哪些参数由系统建议；
- 哪些参数由用户确认；
- 哪些字段缺失或使用了代理；
- 参数变化如何影响结论。

## 12. 与 InvestmentThesis 的接口

成长预期资本化诊断至少向 `InvestmentThesis` 提供：

- `current_business_value_range`
- `priced_growth_share_range`
- `implied_growth_rate`
- `implied_high_growth_duration`
- `credible_growth_range`
- `expectation_overdraft`
- `key_assumptions`
- `evidence`
- `counter_evidence`
- `unknowns`
- `what_would_change_my_mind`
- `quality_status`

建议将以下内容转译为 Thesis 语言：

```text
市场当前主要在为什么未来付费？
哪些经营结果是当前估值成立的必要条件？
哪些指标一旦落后，意味着预期透支正在暴露？
哪些新证据能够证明原先看似激进的预期其实合理？
```

Agent 可以对假设提出不同观点，但不得：

- 修改底层事实数据；
- 隐藏模型警告；
- 把市场共识写成事实；
- 把 diagnostic 数值表达为确定内在价值；
- 在缺失输入时凭空补齐数值。

## 13. 状态与失败语义

### 13.1 `calculation_status`

| 状态 | 含义 |
|---|---|
| `complete` | 所选 V0 情景均完成计算 |
| `partial` | 部分情景完成，部分因数据或数值原因失败 |
| `not_evaluable` | 关键输入不足或模型不适用 |
| `failed` | 数据读取、单位校验或计算过程异常 |

### 13.2 必须显式区分的失败原因

- `source_failed`
- `record_not_found`
- `invalid_value`
- `stale_data`
- `unit_mismatch`
- `insufficient_history`
- `maintenance_capex_unconfirmed`
- `mature_peer_anchor_missing`
- `research_coverage_missing`
- `model_not_applicable`
- `no_finite_solution`

不得把以上状态静默转换为 0、行业平均或默认成功。

## 14. 验收标准

### 14.1 产品验收

1. 同时输出未来价值占比和已前置兑现年限。
2. 用户能够选择固定增长率或固定增长年限的 reverse 模式。
3. 关键假设均可见、可修改、可保存。
4. 输出至少包含保守、基准、乐观三个情景。
5. 结果明确标记为 diagnostic，不输出机械交易建议。
6. 数据不足时输出 `not_evaluable`，不生成伪精确数值。

### 14.2 数值与工程验收

1. 所有金额单位、股本口径和币种经过统一校验。
2. 相同输入和相同参数必须得到可复现结果。
3. 关键计算提供单元测试和边界测试。
4. 折现率、增长率和年限的敏感性变化符合经济直觉。
5. 不存在增长率和增长年限同时无约束求解。
6. 两个价值锚差异过大时触发 warning，而不是机械平均。
7. 负利润、负现金流、金融股和强周期顶部样本能够正确拒绝或切换模型。
8. 输出保存 input snapshot、assumption snapshot、版本和 provenance。

### 14.3 数据验收

V0 至少在以下类型的真实样本上验证：

- 高 ROIC、现金流良好的成长股；
- 高增长但高资本开支公司；
- 研发投入较高的成长公司；
- 周期顶部高增长公司；
- 利润为正但现金流较差的公司；
- 高估值但增长持续兑现的历史正例；
- 估值透支后增长不及预期的历史反例。

样本验证必须检查：

- 结论是否符合当时可获得的信息；
- 参数变化是否导致合理的结论变化；
- 是否能够区分“高估值但合理”与“高估值且透支”；
- 是否出现系统性低估资本密集型或研发型公司的问题。

## 15. 建议开发阶段

### 阶段 0：设计与数据合同

- 固定字段语义、单位和状态；
- 定义用户确认参数；
- 明确模型适用行业；
- 建立 golden cases；
- 不接入 G1/G2 runtime。

### 阶段 1：V0 独立计算器

- 实现双锚 EPV proxy；
- 实现两种 reverse 模式；
- 实现敏感性分析；
- 输出结构化诊断结果；
- 只使用冻结 fixture 和受控真实样本验证。

### 阶段 2：数据补强

- 财务历史由三年扩展到更长周期；
- 补充现金、有息债务、折旧摊销和营运资本；
- 改造研报数据，保留多年度预测路径和分布；
- 建立成熟期同行选择机制；
- LongPort/Longbridge 只在 probe 合格后进入 canonical snapshot。

### 阶段 3：G2 集成

- 接入 research dossier；
- 接入 `InvestmentThesis`；
- 验证 Agent 是否正确引用而非篡改数值；
- 与强单 Agent/Council A/B 一起进行质量评估；
- 不改变 G1 主排序。

### 阶段 4：V1 与 G3 基线

- 升级完整 EPV/reverse DCF 或 economic profit；
- 引入 ROIC、再投资率和多阶段增长路径；
- 保存持仓建立时的隐含预期；
- G2 Gate 通过后，为 G3 提供预期兑现监控输入。

## 16. 主要风险

### 16.1 伪精确

模型可能输出带小数点的增长年限，给用户造成高精度错觉。

应对：

- 默认输出区间；
- 展示敏感性；
- 对外文案使用“大约”“情景下”“依赖假设”等表达；
- 不把单点结果作为最终结论。

### 16.2 系统性低估成长股

将全部资本开支视为维护性投入，会低估现有业务价值并夸大预期透支。

应对：

- 维护性资本开支比例必须由用户确认；
- 同时展示多个比例情景；
- V1 补充折旧、产能、研发和再投资分析。

### 16.3 行业锚自身高估

行业整体可能处于泡沫，简单行业平均无法代表成熟期合理估值。

应对：

- 不直接使用全行业平均；
- 优先使用成熟期可比公司集合；
- 保存同行选择依据；
- 将交叉锚作为验证，不作为唯一真值。

### 16.4 市场预期数据稀疏

小市值公司可能没有有效研报覆盖，热门公司又可能出现共识拥挤。

应对：

- 共识缺失不阻断公司事实分析；
- 共识仅作为市场预期证据；
- 同时保存覆盖数、分布和修订信息；
- 不以目标价均值替代价值判断。

### 16.5 能力目标偏移

实现过程可能重新滑向“做一个复杂 DCF 工具”，偏离帮助用户理解市场隐含假设的目标。

约束：

> 核心验收不是模型有多复杂，而是能否可靠、透明地解释当前价格要求公司未来做到什么。

## 17. 最终产品原则

本能力遵循以下原则：

1. 高估值不等于没有价值，高估值意味着需要更强的未来经营证据。
2. 当前价格不是结论，而是一组等待被反推和验证的市场假设。
3. 模型负责暴露假设，用户负责确认假设。
4. 区间和敏感性优先于单点目标价。
5. 公司事实、市场预期和用户判断必须物理分区。
6. 缺失数据意味着降低结论等级，而不是自动补默认值。
7. V0 是诊断工具，不是决策 Gate。
8. 最终交易决定始终由用户作出。
